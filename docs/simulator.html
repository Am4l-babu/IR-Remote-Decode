🧠 How the Real Decoder Works

This simulator mirrors the exact pipeline running on the ESP8266 firmware in src/main.cpp — only the IR photons are fake.

1
Button pressAn IR LED in the remote pulses at 36–38 kHz, encoding address + command bits per protocol timing.
2
TSOP1738 sensorDemodulates the carrier and outputs an active-low digital replica of the pulse train on its OUT pin.
3
GPIO2 captureThe ESP8266's IRrecv timer-interrupts on every edge and records mark/space durations into a 1024-entry buffer.
4
IRremoteESP8266Matches the timing pattern against known protocols and decodes the hex code, bit count and protocol name.
5
WebSocket pushThe result is JSON-broadcast on port 81 to every connected browser tab in real time.
6
Web dashboardThe page you're using right now (in hardware mode) animates, logs, and optionally saves the code to LittleFS.
🔌 Wiring & Hardware

The real sensor side of this project — for when you're ready to move off the simulator and onto the breadboard.

  • 1× ESP8266 dev board (NodeMCU / Wemos D1 mini)
  • 1× TSOP1738 (38 kHz) IR receiver module
  • 3× Male–female jumper wires
  • — Optional: 100 Ω series resistor + 10 µF cap across VCC/GND for noisy supplies

⚠️ TSOP1738 is 5V-tolerant on most breakout boards but check your specific module — the ESP8266 GPIOs are 3.3V only. When in doubt, power the sensor from 3V3, matching IR_RECV_PIN = 2 (D4) in src/main.cpp.

Part of the IR-Remote-Decode project. Flash src/main.cpp to real hardware to replace this simulator with a live sensor feed.
